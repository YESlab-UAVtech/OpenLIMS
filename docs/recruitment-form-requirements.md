# 模块化报名表需求清单

日期：2026-10-12。状态：用户已审核通过；第一批基础能力已完成并通过后端验证，第二/三批尚未施工，整体功能尚不可交付。

## 1. 已确认的需求

- 维护一份全局报名表，由多个独立模块按指定顺序组成；不按招新批次配置多套表单。
- 具备报名管理权限的账号可以编辑模块、设置内容和调整顺序；普通成员及报名者不能修改模板。
- 支持选择、自由填写和内容上传模块；上传第一版支持图片和 PDF。
- 现有技术认知题保留为可启用的独立模块，启用时沿用随机分配 5 道、至少回答 3 道的规则。

## 2. 模块与可编辑内容（拟定）

| 模块          | 用途与配置                                                                                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 基础信息      | 姓名、邮箱、专业、班级等现有身份资料；可调整标题、说明及位置。姓名、邮箱、专业、班级保留必填，防止转正建档缺少核心资料。其他已有字段沿用默认配置。全表只出现一次。 |
| 选择          | 单选或多选，设置问题、说明、选项、必填及最少/最多选择数。可添加多个独立模块。                                                                                      |
| 自由填写      | 单行、多行文字，设置问题、说明、占位提示、必填和长度限制；邮箱/电话/链接使用对应格式校验。可添加多个模块。现有个人链接列表作为链接填写子类型保留。                 |
| 内容上传      | 设置标题、说明、必填、允许图片/PDF、数量及大小限制；可添加多个模块，例如作品图片、项目报告。                                                                       |
| 技术认知      | 通过启用/停用决定新报名是否需要作答；全表最多一个，题库及 5 选 3 规则本批不改。                                                                                    |
| 说明/分组标题 | **建议新增**：插入填写说明、材料要求或章节标题，将长表单分段；不收集答案、不计入必填检查，可重复添加。                                                             |

新增模块不是新增测验业务。保留 `QUIZ_MANAGE`、`QUIZ_PARTICIPATE`、`QUESTION_WRITE` 等现有预留权限。

## 3. 管理端交互

- 在现有“招新管理”内增加“报名表设置”，不新增独立一级后台栏目。
- 支持添加、复制、编辑、删除普通模块，启用/停用技术模块，调整模块及选择项顺序；提供上移/下移操作，拖动排序可作为补充，不依赖拖动才能完成操作。
- 核心基础信息模块不能删除或停用。标题、说明、非核心字段与模块位置可编辑；不可把系统身份字段改成其他含义或解除必要校验。
- 分开“保存草稿”“预览”“发布报名表”；草稿不影响正在报名的页面。预览使用与报名者相同的渲染规则，并能查看手机布局。
- 删除模块/选项、未保存退出及发布需要明确反馈；非法配置就地提示，失败保留输入。
- 修改配置、发布新版本记录操作者和时间；并发编辑发现旧版本时提示刷新，不覆盖他人的修改。

## 4. 版本与已有报名（拟定）

- 首次成功提交时，报名绑定一份不可变的已发布表单版本；在初筛前修改报名也使用原版本。
- 发布新版只影响之后首次提交的新报名，不把新增必填题强加给旧报名，不丢弃或重排历史答案。
- 尚未提交的填写者遇到管理员发布新版，提交时提示表单更新；尽可能保留 ID、类型和选项仍相容的输入，重新核对后再提交，不能静默改题或丢答案。
- 既有存量报名继续按旧表单显示与审核；不改存量阶段、状态、回答、图片或成员资料。
- 初筛后报名者不可编辑正文或上传/移除附件，继续沿用现行招新锁定规则。管理员在审核详情中按当时表单顺序读取各模块答案。

## 5. 附件及限制（拟定）

- 图片支持 JPG/PNG/WebP，默认单张最大 5MB；PDF 默认单份最大 10MB。每个上传模块默认最多 6 份，全表最多 20 份、合计最大 50MB；管理员可设更小限制，不突破服务端上限。
- 提供文件名称、大小、上传结果、重试和移除操作；图片可预览，PDF先提供鉴权下载。已有作品图片继续可读。
- 附件仅申请者本人和有 `RECRUITMENT_MANAGE` 权限的人可访问，不生成公开下载地址；服务端校验真实格式、文件大小、归属与当前报名阶段。
- 模板默认最多 50 个模块、每个选择模块最多 30 个选项；默认不加入条件分支、复杂计算或可执行 HTML。
- 当前浏览器本地草稿继续可用；未提交的文件需重新选择时必须说明，不能只显示文件名却把它当成已上传。

## 6. 默认表单与范围

初始已发布版本按现有报名表生成：基本信息、兴趣方向、现有技能、意向标签、自我介绍/经历、个人展示与链接、作品上传、技术认知题；保留现有填写能力和默认必填规则。管理者之后可在新版本中调整普通模块及其必填性，技术模块可停用；核心基础信息继续保留。

本批不改变报名→初筛→面试→技能测试→正式成员流程，不引入多套表单、批次业务、问卷分析、自动评分、测验、导出或条件显示规则。

## 7. 验收

- 管理者可以保存配置、排序、预览和发布；普通成员/游客直接调用管理接口也被拒绝。
- 两个以上选择、填写或上传模块按顺序组合，答案准确归属模块；服务端执行必填、选项、数量、长度、文件限制与身份绑定校验。
- 技术模块启用/停用都能完成新报名；已绑定旧版本的报名不受开关影响。
- 已提交和存量报名的题目/答案完整保留，初筛后不可编辑；版本更新提示、并发编辑和发布无数据覆盖。
- 附件鉴权、越权拒绝、上传失败/重试及图片/PDF格式检测通过；不删除既有业务上传文件。
- 前后端测试、实际 MySQL 迁移演练与真实浏览器截图分别记录，不能互相替代。截图按仓库规定视口、主题及预设保存到 `.codex-run/ui-review/`。

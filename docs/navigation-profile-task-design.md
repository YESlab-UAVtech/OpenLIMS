# 导航、个人主页与任务管理整合设计

日期：2026-10-12。状态：用户已审核通过并完成施工；验证见 DEVLOG 同日记录。
需求依据：`docs/navigation-profile-task-requirements.md`。颜色与交互沿用 `design-system/openlims/MASTER.md` 及现有页面覆盖。

## 1. 现状

- `PortalShell.vue` 固定渲染“更多”和“后台管理”两个下拉；公开首页的讨论入口为路由链接，其余栏目为锚点，需统一导航样式。
- `TodayView.vue` 与 `ProfileView.vue` 各自取积分和日程；`PublicMemberView.vue` 仅展示公开档案与讨论内容。
- `AdminTasksView.vue` 的三个分类链接进入三个页面；`AdminOnboardingTaskView.vue`、`AdminBountiesView.vue` 有各自标题，`AdminLayout.vue` 有独立悬赏管理入口。
- 每日积分汇总已由 `PointService.ownSummary()` 提供，日期采用实验室时区；公开主页资格由 `MemberProfileService.getPublicProfile()` 校验。

## 2. 导航

- 公开首页统一 `.top-nav` 内锚点和路由链接的行高、内联布局、垂直居中和触控高度，不用逐字位移修补。
- `PortalShell` 将现有成员链接整理为一份按身份可见的导航数据，移除返回公开首页链接，合并今日/个人主页入口；后台管理为指向 `/admin` 的普通链接。
- 以容器实际宽度减去品牌和账号区域宽度得到导航预算；用隐藏且不可聚焦、对辅助技术隐藏的测量区测量完整链接组。`ResizeObserver`、字体加载和导航内容变化后重新计算，卸载时清理监听。
- 只有完整导航超出预算时才显示“更多”，将尾部入口移入菜单，空间恢复后重新展开。计算包含“更多”按钮宽度，避免在临界宽度反复切换。维持原有菜单 Esc、外部点击关闭、键盘焦点和当前页提示。
- 公开顶栏也按实际内容是否放得下判断栏目折叠，保持其锚点与移动端账号位置。

## 3. 统一个人主页

- `ProfileView` 作为统一页面，提取今日内容为不含 `PortalShell` 的组件/数据逻辑。一个页面只保留一份标题、个人日程和积分读取结果；热力图复用 `PointsHeatmap.vue`。
- 桌面以今日待办为主要区域、日程为辅助区域；下方展示档案、积分总览和悬赏推荐，手机依次堆叠。密码修改保留在页面下方的账号设置区域。
- `/today` 重定向到 `/profile`，更新登录后跳转、公开页账号链接、命令面板与站内默认返回地址；保留资料补全守卫及 `/profile/edit`。
- 各内容独立处理加载失败，档案或热力图失败不影响待办与其他已加载内容；沿用服务端任务状态、冻结规则与真实数据。

## 4. 他人可见热力图

- 增加公开成员每日积分汇总接口（拟 `/api/v1/public/member-profiles/{profileId}/points`）。先执行与公开详情一致的成员资格校验，再读取积分聚合。
- 独立公开 DTO 只含 `totalPoints`、`dailyPoints` 及必要的日期边界/服务端今日日期；不直接返回本人 `MemberSummary`（含流水和分类统计）。复用现有每日聚合查询，范围与本人热力图一致，不修改表或迁移。
- `PublicMemberView` 使用同一热力图组件；公开场景隐藏指向本人积分流水的入口。路由成员变化时刷新数据，处理空积分、失败与重试。
- 用后端测试验证公开成员可读、未公开/不存在成员拒绝、公开响应字段边界及同日期聚合口径。

## 5. 统一后台任务管理

- 建立持久任务管理容器，统一 `PortalShell` 标题与三类导航，分类状态写入 `/admin/tasks?type=standard|onboarding|bounty`，默认普通任务。
- 从既有三个视图提取内容组件，移除分类内部重复的页面标题、外壳与返回任务管理链接；分类保留各自表单、筛选与加载状态，不跨类复用业务状态。
- 切换分类继续使用未保存保护；普通任务/悬赏编辑沿用抽屉，新手共享任务设置、子任务和审核保持既有操作。更新主按钮位置，避免嵌套页头。
- `/admin/tasks/onboarding`、`/admin/bounties` 兼容跳转到对应分类，保留所需参数；普通任务进度、子任务编辑和悬赏接取名单/履约详情继续使用原地址并返回相应分类。
- `AdminLayout` 移除独立“悬赏管理”，原悬赏详情归属“任务管理”面包屑和侧栏高亮；总览、命令面板和模块内返回链接同步指向统一入口。

## 6. 实施与验证

审核通过后先调整导航，再整合个人主页和公开积分接口，最后提取任务分类容器并更新使用文档与设计覆盖。只实施需求列明的界面和读取接口，不改变任务业务服务。

执行 `npm run check`、公开积分接口相关后端测试及前后端联调。浏览器核对顶栏临界宽度与角色、公开热力图、本人与他人信息边界、三类切换、未保存保护、旧链接、刷新与历史导航；按需求中的视口/主题/预设矩阵截图。临时服务按本次验收范围启动和收尾，记录结果与未验证事项到 `DEVLOG.md`。
